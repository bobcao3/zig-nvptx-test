# ptxas reproductions

Each file in this folder reproduces one ptxas problem without the Zig compiler, with as little code
as the problem needs. The first line of each file gives the build and run commands. The last column
names the workaround of the Zig backend or `std.nvptx` and the cases that the workaround leaves.

| File | Problem | Seen with | Workaround |
|---|---|---|---|
| `warpsync_hoist.cu` | ptxas places the warp synchronization of a CTA barrier right after a divergent spin loop, above the store that releases the lock. The lanes that still spin never see the release, and the warp deadlocks. | ptxas 13.0 and 13.4 for sm_121. The CUDA 13.0 driver when it compiles `sm_80` PTX for an sm_121 device. | `std.nvptx` emits `bar.warp.sync -1` before each CTA barrier. |
| `minmax_cvt_crash.cu` | A `min` or `max` of `.f16x2` or `.bf16x2` with a constant, a `cvt.u16.u32` of the result and a `setp` against the low half of the constant crash ptxas at `-O1` and above for sm_90 to sm_103. | Segmentation fault: ptxas 12.8 and 13.0. Internal compiler error C7907: ptxas 13.1 and 13.3. ptxas 13.4 builds the file for every target, and every version builds it for sm_120. | `intConvert` masks the source with `and.b32` before the `cvt`. |
| `recursive_call.ptx` | ptxas crashes on a direct call to a recursive `.func` when the optimizer proves the call unreachable. nvcc does not emit this PTX. | ptxas 12.8, 12.9, 13.0, 13.1, 13.3 and 13.4, and the CUDA 13.0 driver. ptxas 13.0 and 13.4 crash for sm_90 and sm_121 and build the file for sm_80. | The backend lists each function on a call cycle in a module-level table of function addresses. |
| `dead_call_recursion.cu`, `dead_call_function_table.cu` | ptxas crashes when it removes a call to `g` that never runs, and the caller of `g` is a recursive function or a function whose address the module takes. | ptxas 13.0 and 13.4 for sm_90 to sm_121 at `-O1` and above, and the CUDA 13.0 driver. sm_80 and `-Xptxas -O0` build the files. | The table of function addresses also lists each function whose address the module takes and each function that a listed function calls. |
| `call_result_offset.cu` | ptxas adds a 64-bit constant outside the signed 32-bit range to the result of the first of two calls and gives that sum to the second call too. The internal routine of 64-bit `div` and `rem` is such a call. | ptxas 13.0 and 13.4 for sm_120 and sm_121 at `-O1` and above. The CUDA 13.0 driver when it compiles `sm_80` PTX for an sm_121 device. | The backend adds such a constant on the 32-bit halves with `add.cc` and `addc`. |
| `divergent_division.cu` | On one side of a divergent branch, a 32-bit division converts the divisor to float (`UI2F.U32.RP`) into a uniform register that holds a value of the other side. | ptxas 13.0 and 13.4 for sm_120 and sm_121 at `-O2` and above. | The backend divides by a constant with a multiply-high sequence. A division by a run-time value keeps the problem, in Zig code and in CUDA code. |
